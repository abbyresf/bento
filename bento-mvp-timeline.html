Key Risks to Watch

Dining API instability The Nutrislice API is unofficial. Menu format changes or downtime will break meal generation. Mitigation: robust fallback to cached data, monitoring alerts.
Multi-university data variance Each school's dining system structures data differently. Budget extra time per university beyond the first — the adapter pattern helps but won't eliminate all edge cases.
Auth complexity Migrating from no-account to accounts is the biggest scope risk. Scope it tightly in Phase 1 — don't add social login until post-launch.
Scope creep Four months is tight. If Phase 1 or 2 slip, drop the email digest before cutting any core features. Streaks and insights are differentiators — protect those.
